# 数字游牧 ERP 正式上线前回归检查清单

> 适用时间：每次正式发布前  
> 建议执行人：业务负责人 + 财务/销售操作人各 1 人

## 0. 发布前配置确认

- [ ] Cloudflare / Pages 环境变量已配置：
  - [ ] `CLOUDFLARE_API_TOKEN`
  - [ ] `MASTER_ACCOUNT`
  - [ ] `MASTER_PASSWORD`
  - [ ] `ANTHROPIC_API_KEY`
  - [ ] `GEMINI_API_KEY`
  - [ ] `SILICONFLOW_API_KEY`
- [ ] 生产后端地址、KV 绑定、资金账户、基础资料可正常访问
- [ ] 当前分支 `typecheck` 与 `build` 已通过

## 1. 账号与安全

### 注册 / 登录
- [ ] 新用户注册成功
- [ ] 新用户可正常登录
- [ ] 错误密码会被拦截
- [ ] 被暂停账号无法登录

### 试用账号限制
- [ ] 试用账号可访问登录、用户信息、企业信息
- [ ] 试用账号访问受限业务接口时会提示体验版限制

## 2. 销售合同主链路

### 新建合同
- [ ] 可选择客户、经办人、资金账户
- [ ] 可添加商品并自动汇总金额
- [ ] 折扣、物流费、其他收支能正确影响最终应收
- [ ] “实际待收” = 最终应收 - 预付款核销 - 本次收款

### 合同收款联动

#### 场景 A：仅本次收款
- [ ] 合同保存并审核后，只生成 1 笔“合同自动收款”
- [ ] 收款金额 = `receive_amount`

#### 场景 B：仅预付款核销
- [ ] 合同保存并审核后，只生成 1 笔“预付款核销”
- [ ] 金额 = `prepay_amount`

#### 场景 C：预付款 + 本次收款
- [ ] 审核后生成 2 笔收款单
- [ ] 一笔为“预付款核销”
- [ ] 一笔为“合同自动收款”
- [ ] 两笔合计不超过最终应收

#### 场景 D：无收款
- [ ] 可保存合同
- [ ] 审核后不自动生成多余收款

### 合同反审核
- [ ] 若存在手工收款单，反审核会被拦截
- [ ] 若只有系统自动收款单，反审核后会自动删除这些自动收款单
- [ ] 来源报价单状态会回退

### 运费费用联动
- [ ] 我方承担运费时，审核后生成 1 笔销售运费费用
- [ ] 重复审核不会重复生成费用
- [ ] 反审核后该笔系统运费费用会被撤回

## 3. 财务主链路

### 收款单
- [ ] customer 类型可保存
- [ ] supplier 类型可保存
- [ ] staff 类型可保存
- [ ] other 类型可保存
- [ ] 删除收款单后列表会刷新

### 付款单
- [ ] 单账户付款可正常保存
- [ ] 多账户付款时会按账户拆成多笔付款单
- [ ] 每笔付款单对应正确的资金账户

### 预付款
- [ ] 新增预付款后余额更新正确
- [ ] 已核销预付款不可删除
- [ ] 删除未核销预付款后资金账户余额回退正确

## 4. 本地配置与缓存

- [ ] 客户等级、等级价在当前账号下可读写
- [ ] 更换账号后，不会串用其他账号的等级价/提成配置
- [ ] 供应商分类在当前账号下独立存储
- [ ] “初始化所有数据”后仅退出登录，不会误删本地业务配置

## 5. 最终验收

- [ ] 首页、销售、财务、采购、仓库可正常打开
- [ ] 控制台无阻断报错
- [ ] 核心报表金额与业务单据抽样一致
- [ ] 至少完成 1 次完整业务演练：
  - [ ] 客户下单
  - [ ] 合同审核
  - [ ] 收款/预付款核销
  - [ ] 出库/退货
  - [ ] 财务核对

## 建议上线顺序

1. 先用测试账号完整跑一遍合同—收款—反审核—再审核流程  
2. 再用真实业务账号录入 1 笔小额测试单  
3. 最后再正式启用整套业务
