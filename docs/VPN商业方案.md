## 一、项目概述

### 1.1 产品定位

开发一款类似"神灯"的全平台 VPN/安全上网工具，提供：
- 稳定高速的跨境网络连接
- 智能分流（国内直连、海外加速）
- 全平台覆盖（macOS / Windows / iOS / Android）
- 从个人工具逐步发展为付费订阅制商业产品

### 1.2 市场参考

参考产品"神灯"(Shendeng) 的技术架构：
- 采用 WireGuard 协议（速度快、代码精简）
- GeoIP + GFW 域名列表实现智能分流
- 多 API 域名容灾，防止单点故障
- Flutter 跨平台客户端
- JWT 认证 + 手机号注册 + VIP 会员体系

## 二、技术架构

### 2.1 整体架构图

```
┌──────────────────────────────────────────────┐
│             用户端（全平台 Flutter App）         │
│  ┌──────────┐  ┌──────────┐  ┌─────────────┐ │
│  │  macOS   │  │   iOS    │  │Android/Win  │ │
│  │SystemExt │  │NetworkExt│  │VpnService   │ │
│  └────┬─────┘  └────┬─────┘  └──────┬──────┘ │
│       └──────────────┼───────────────┘        │
│              ┌───────┴───────┐                │
│              │  sing-box 引擎 │                │
│              │ (Go 编译为原生库)│                │
│              └───────┬───────┘                │
└──────────────────────┼───────────────────────┘
                       │
          ┌────────────┼────────────┐
          │ HTTPS      │            │ WireGuard / VLESS
          ▼            │            ▼
   ┌──────────┐        │     ┌──────────────┐
   │ API 服务器 │        │     │  VPN 节点集群  │
   │ Go + PG   │◄───────┘     │  sing-box ×N  │
   │ + Redis   │──── gRPC ───►│  全球分布      │
   └──────────┘              └──────────────┘
```

### 2.2 核心引擎：sing-box

选择 [sing-box](https://github.com/SagerNet/sing-box) 作为统一 VPN 引擎，而非分别集成 WireGuard + Xray：

| 优势 | 说明 |
|------|------|
| 多协议合一 | 单一引擎支持 WireGuard、VLESS、VMess、Shadowsocks、Hysteria2 |
| 内置路由 | GeoIP/GeoSite 分流引擎，无需额外开发 |
| 全平台 TUN | 原生管理各平台虚拟网卡 |
| 成熟稳定 | SFI、SFA、NekoBox 等知名客户端均基于此 |
| Go 语言 | 通过 gomobile 编译为 iOS/Android 原生库 |

### 2.3 协议策略

| 协议 | 角色 | 端口 | 特点 |
|------|------|------|------|
| WireGuard | 主协议 | UDP 非标准端口 | 速度最快，延迟低 |
| VLESS + Reality | 备用协议 | TCP:443 | 抗封锁能力极强，伪装为正常 HTTPS |

**自动切换逻辑**：客户端优先使用 WireGuard，若连接失败（端口被封）自动降级为 VLESS+Reality。

### 2.4 智能分流原理

```
用户请求 → DNS 查询
  ├─ 匹配 GeoSite:cn → 使用国内 DNS（223.5.5.5）→ 直连
  ├─ 匹配 GeoSite:gfw → 使用远程 DNS（1.1.1.1）→ 走代理
  └─ 其他 → 默认走代理

用户请求 → IP 路由
  ├─ 匹配 GeoIP:cn → 直连（不经过 VPN）
  ├─ 匹配 GeoIP:private → 直连（局域网）
  └─ 其他 → 走 VPN 代理
```

三种用户可选模式：
1. **智能分流**（推荐）：国内直连 + 海外走代理
2. **全局代理**：所有流量走 VPN
3. **仅直连**：关闭代理（调试用）

## 八、关键技术挑战与解决方案

### 8.1 iOS 内存限制

**问题**：iOS NetworkExtension 独立进程，内存上限 50MB。

**方案**：
- sing-box 精简编译，禁用不需要的协议
- 使用 SRS 二进制格式加载规则（比 .dat 省内存）
- 参考开源项目 [sing-box-for-apple](https://github.com/SagerNet/sing-box-for-apple)

### 8.2 抗封锁检测

**问题**：GFW 深度包检测可能识别并封锁 VPN 流量。

**方案**：
- WireGuard UDP 流量本身无固定特征，使用非标准端口
- VLESS + Reality 伪装为正常 HTTPS 访问（如 microsoft.com），主动探测也无法识别
- 自动降级机制：WireGuard 失败 → VLESS+Reality → CDN WebSocket（终极方案）

### 8.3 连接稳定性

**问题**：移动端 Wi-Fi/蜂窝切换导致断连。

**方案**：
- WireGuard 原生支持漫游（基于 session 而非 connection）
- 25 秒 keepalive 保持 NAT 映射
- 网络变化监听 + 自动重连（iOS: NWPathMonitor, Android: ConnectivityManager）

### 8.4 API 容灾

**问题**：API 域名被封，客户端无法获取节点列表。

**方案**（学习神灯做法）：
- 客户端内置 3-4 个备用 API 域名
- CloudFront CDN 分发
- 硬编码 IP 作为最后 fallback
- 域名轮询 + 健康检查

### 8.5 应用商店上架

**问题**：Apple/Google 对 VPN 类 App 审核严格。

**方案**：
- 定位为"网络安全工具"/"隐私保护"，不提"翻墙"
- 使用 Apple 官方 NetworkExtension API（不用私有 API）
- 准备正规公司主体和隐私政策
- 中国区考虑 TestFlight / APK 直接分发

## 十、总结与建议

### 可行性评估

- **技术可行性**：高。核心引擎 sing-box 开源成熟，Flutter 跨平台方案已验证（神灯本身就用 Flutter）
- **市场需求**：持续存在，且用户付费意愿强
- **投入产出比**：初期投入低（~$34/月），50 个付费用户即可盈利

### 建议执行路径

```
第 1 步 → 购买服务器，部署 sing-box 节点（1天）
第 2 步 → 搭建 API 服务器基础框架（1-2周）
第 3 步 → Flutter 客户端 macOS 版（3-5周）
第 4 步 → 自用验证 + iOS 版（3-4周）
第 5 步 → 评估体验后决定是否商业化
```

**核心观点**：先用最小成本做出可用产品自己用，验证稳定性和体验后，再决定是否投入商业化。这样风险最低，试错成本约 ¥250/月。
